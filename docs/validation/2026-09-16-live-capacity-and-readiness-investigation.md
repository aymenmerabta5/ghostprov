## Corrective work and remaining limits

- Host and R10 Awareness publication now filters outbound updates to the provider's own identity, removing the verified remote-update echo while preserving incoming state and query behavior. Sustained eight-project reliability and longer shared-fleet workloads remain unproven.
- Receive recovery now uses fresh sidecar pending-work and host accepted/processed progress evidence. It distinguishes a lost incoming flight or return ACK from provider thinking and client/memory backpressure; reconnect preserves immutable execution state and does not resubmit provider work.
- New bootstrap attempts persist validated command acceptance and retain bounded exact-session execution diagnostics. Missing or invalid acceptance, failed persistence, old receipts and absent peers remain ambiguous; they never authorize replay or deletion of old journals.
- A bounded legacy migration plan was prepared at 00:55:57.204 UTC for exactly workers 4, 6 and 11, using three grants beyond the ordinary four-hold budget and a hard total of seven. Its saved summary records `sourceJournalsUnchanged:true` and `productionLedgerWritten:false`. **The production migration ledger was not activated.** The plan does not prove cleanup, restore those workers, or authorize deleting their held projects.
- Standalone-search waiting is abort-aware, separately attributed and subject to its ingress deadline before router entry. This addresses queue attribution rather than proving the original live failure eliminated.
- The Codex model catalog now advertises `default_reasoning_summary:"auto"`. This selects a summary default for supporting clients; it does not lower reasoning effort, cap thinking, alter output limits, or terminate a quiet provider request. Explicit caller reasoning settings remain exact, and native HTTP/WebSocket summary events are forwarded unchanged. The provider controls when summaries appear.
- Shutdown control rechecks startup-gate ownership immediately before its after-cleanup/poweroff step. System cleanup also rejects a retained manifest `bootstrap_hold` even if its journal file is absent. These are implemented, offline-verified guards; the already-running server does not acquire them from disk edits, and its schema-1 descriptor does not establish its loaded source revision.
- Subsequent independent verification reproduced a bootstrap fairness defect: after a first readiness failure leaves cleanup debt, recovery could consume a cold-start permit and enter the new-child path before the cleanup-only gate was armed. The correction checks authoritative journal and exact lifecycle debt before cold admission, distinguishing cleanup not required, proven and unproved. It passed 71 focused tests and the 3,240-test suite. The first two eight-project runs preceded it; the later `proof-gAKNCI` used eight backends for eight commands and kept worker 8's subsequent recovery on the cleanup-only path without another cold slot. That bounded observation does not establish full fleet reliability.
- Two CONTROL recovery gaps found after `proof-jyl3a5` are now corrected: the host waits for an already-owned bounded probe before one explicit CONTROL repair, and the R10 sidecar can use newer mirrored CONTROL revisions only as a bounded reconnect hint. The detailed authority limits and offline validation appear below. Their successor bundle was exercised by `proof-0eZX0F`, which failed during load and exposed further host gaps.
- A later shutdown investigation found that the router's idle wait could consume the entire shared shutdown deadline before fleet cleanup began. The host now reserves a bounded cleanup phase within that unchanged deadline. Focused and complete-suite validation passed; independent review found no introduced finding. The later run originally verified seven cleanups and reported aggregate shutdown failure; a separate finalizer subsequently verified the eighth deletion without changing that original result.
- Current-host and actual-R10 socket-factory tests independently reproduced a valid URL/token rotation that connected the old endpoint with the new token. A shared socket-target helper now uses one current credential snapshot for URL, document and token across all four request/supervisor factories, while keeping the original document fixed. No endpoint-change evidence was captured for `proof-jyl3a5`, so this is a corrected independent defect rather than a proven cause of that incident.
- After `proof-0eZX0F`, the router's committed-handle proof cap increased from 60 to 180 seconds while retaining the existing `min(queueTimeoutMs + 25 ms, cap)` bound. It waits for the same execution and handle; it does not retry a committed request. Focused checks and independent review passed.
- Receive-lane selection now identifies CONTROL loss only when fresh native DATA covers the sidecar's latest sampled DATA-publication count. Old prepared-frame duplicates no longer misidentify an unseen new DATA flight as a lost return ACK. Focused actual-session/runtime checks and independent review passed; original pending-work, backpressure and thinking guards remain.
- A queued credential rotation can time out behind cancellation frames before any rotation frame is published. Overlapping relaunch handling then treated that rejection as fatal while the original recovery episode still had time remaining. The completed correction keeps one reconnect/rotation owner, permits one exact-timeout same-session repair, and observes fresh bound progress through the original deadline. A relaunch rechecks its source after any awaited rotation before retirement. Focused, complete-suite and independent-review gates passed.
- R10's former 60-second prepared-body retention could expire while bounded host admission/recovery was still completing. The default is now 360 seconds in the R10 engine only; explicit shorter overrides and immediate cancellation/drain cleanup remain. Frozen R1–R9 behavior and the shared schema are unchanged.

- The verifier derives frame-kind categories from the protocol descriptor and records bounded content-free error evidence. The old verifier omitted several control/error kinds, so absence of a named kind in those historical logs cannot prove the frame was unpublished.
